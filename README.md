# hackathon-clip-deck

Презентация «Скрепка для Додо ИС» — рыба презентации к хакатону.
Один самодостаточный HTML-файл: весь CSS и JS внутри, внешних зависимостей нет.

Открыть: **https://hackathon-clip-deck.dodo-ai-platform.io/** (вход по корпоративному Google SSO).

Инфраструктура, kubeconfig и реквизиты — в `PLATFORM.md` (его пишет оператор, руками не редактируем).

## Как это задеплоено

Проект чисто статический: **пода нет**, namespace выделен с нулевой compute-квотой (`pods=0`).
`site/index.html` лежит в бакете `site` (`access: restricted`), платформа отдаёт его маршрутом `/`
за корпоративным SSO. Прямая ссылка на объектное хранилище отдаёт 403 — файлы не забрать в обход входа.

Поэтому в репозитории нет ни `Dockerfile`, ни `k8s/`, ни workflow сборки образа: собирать и катить нечего.

## Обновить презентацию

Правим `site/index.html`, затем заливаем в бакет:

```bash
export KUBECONFIG=~/.kube/config:~/.kube/hackathon-clip-deck.yaml
kubectl config use-context hackathon-clip-deck
for k in AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY S3_ENDPOINT S3_BUCKET S3_REGION; do
  export $k="$(kubectl get secret hackathon-clip-deck-site-credentials \
    -n hackathon-clip-deck -o jsonpath="{.data.$k}" | base64 -d)"
done
python3 scripts/upload-site.py
```

Всё заливается с `Cache-Control: no-cache`: файлы заменяются под одними и теми же именами, поэтому
долгий кэш показывал бы докладчику прошлую версию. Браузер кэширует, но переспрашивает — неизменившийся
файл приходит как 304.

Видео на слайде 2 запускается само, как только слайд показан, и сбрасывается на начало при уходе с него.
Если браузер заблокирует автозапуск со звуком, ролик пойдёт без звука — звук включается кнопкой на плеере.

Точка входа обязана называться `index.html` — это фиксированное имя для статического маршрута.
Ссылки на любые дополнительные файлы делаем относительными (`/assets/…`), а не прямыми URL хранилища:
браузер пойдёт в хранилище напрямую и получит 403.

## Совместные правки (подготовлено, но не включено)

Сейчас «Правка слайдов» сохраняет изменения в `localStorage` — **только в браузере правящего
и только на этом компьютере**. Другие по ссылке видят опубликованную версию. Чтобы правки
видели все, нужен сервис, который примет отредактированный HTML и положит его в бакет:
ключи от бакета в страницу класть нельзя, их достанет любой, кто откроет исходник.

В репозитории уже лежит всё, кроме платформенной заявки:

| Что | Где | Статус |
|---|---|---|
| Сервис сохранения | [service/main.py](service/main.py) | проверен: запись в бакет, бэкап прошлой версии, отказ на чужой HTML |
| Образ | [service/Dockerfile](service/Dockerfile) | по правилам платформы: multi-stage, non-root UID 65534 |
| Манифесты | [k8s/](k8s/) | YAML валиден; серверная проверка недоступна, пока у проекта нет compute-прав |
| CI | [.github/workflows/deploy.yaml](.github/workflows/deploy.yaml) | запуск только вручную, сборка из `service/` |
| Кнопка «Опубликовать для всех» | `site/index.html`, `PUBLISH_URL` | скрыта, пока `PUBLISH_URL = null` |

### Как включить

1. **PR в `dodo-ai-platform/platform-projects`** — в `projects/hackathon-clip-deck.yaml` добавить
   квоту и маршрут сохранения. Маршрут — публичная экспозиция, поэтому PR помечается
   `routes: requires manual approval` и ждёт аппрува CODEOWNERS:

   ```yaml
   spec:
     resources:              # сейчас секции нет: статик-проект, pods=0
       cpu: "500m"
       memory: "512Mi"
     routes:
       - path: /             # как сейчас: просмотр статикой из бакета
         auth: corp
         backend:
           bucket:
             name: site
       - path: /save         # запись — только перечисленным редакторам
         auth: allowlist
         allowedEmails:
           - a.alekhina@dodobrands.io
         backend:
           service:
             name: hackathon-clip-deck
             port: 8080
   ```

2. После мержа и реконсиляции — вернуть в `deploy.yaml` триггер `on: push: branches: [main]`
   вместо `workflow_dispatch`.
3. Поставить в `site/index.html` `var PUBLISH_URL = '/save';` — кнопка появится в панели правки.
4. Запушить в `main`: CI соберёт образ, задеплоит под, и правки начнут сохраняться для всех.

### Что важно понимать

- **Кто правит.** Смотреть могут все сотрудники (`auth: corp`), публиковать — только почты из
  `allowedEmails`. Это разные маршруты, поэтому права разные.
- **Одновременная правка.** Публикуется вся презентация целиком: если двое правят одновременно,
  выиграет тот, кто нажал «Опубликовать» последним. Слияния правок нет.
- **Откат.** Перед каждой записью прошлая версия уезжает в `versions/index-<дата>.html` в том же
  бакете, список отдаёт `GET /versions`.
- **Проверки на входе.** Сервис принимает только UTF-8, только HTML, только с заголовком этой
  презентации и не больше 5 МБ — случайным запросом бакет не подменить.
