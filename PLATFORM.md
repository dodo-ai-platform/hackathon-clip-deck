### Using a bucket (SberCloud OBS, S3-compatible)

Secret keys: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `S3_ENDPOINT`, `S3_BUCKET`, `S3_REGION`. Virtual-hosted addressing; `aws s3`/`mc` need special config — use the AWS SDK or boto3. **The two checksum kwargs are required:** SberCloud OBS rejects the content-checksums botocore ≥ 1.36 sends by default — without them the very first `put_object` fails with `XAmzContentSHA256Mismatch`.
```python
import boto3, mimetypes, os
from botocore.config import Config

s3 = boto3.client('s3', endpoint_url=os.environ['S3_ENDPOINT'],
    aws_access_key_id=os.environ['AWS_ACCESS_KEY_ID'],
    aws_secret_access_key=os.environ['AWS_SECRET_ACCESS_KEY'],
    region_name=os.environ['S3_REGION'],
    config=Config(
        s3={'addressing_style': 'virtual', 'payload_signing_enabled': False},
        request_checksum_calculation='when_required',    # required for OBS (botocore >= 1.36)
        response_checksum_validation='when_required',     # required for OBS (botocore >= 1.36)
    ))
bucket = os.environ['S3_BUCKET']

# Upload a built static site (e.g. ./dist). The entry page MUST be named index.html
# (the route serves index.html / error.html). Set Content-Type or browsers download
# files instead of rendering them.
for root, _, files in os.walk('dist'):
    for f in files:
        path = os.path.join(root, f)
        key = os.path.relpath(path, 'dist')
        ctype = mimetypes.guess_type(path)[0] or 'application/octet-stream'
        cache = 'no-cache' if key == 'index.html' else 'public, max-age=31536000, immutable'
        s3.upload_file(path, bucket, key,
            ExtraArgs={'ContentType': ctype, 'CacheControl': cache})
```
After uploading, reach the files **through the route** (your route `path`, e.g. `/`), not the raw OBS URL.

## Security Constraints

- **Pod Security Standards:** restricted — no privileged containers, no hostPath, no hostNetwork, no hostPID, no host ports
- **NetworkPolicy:** default-deny with exceptions. The operator manages a set of `dap-*` policies in your namespace (one per concern — `kubectl get netpol` reads as a table of contents); `dap-default-deny` blocks everything, the others add allowances:
  - Ingress: allowed from the ingress-controller namespace, from the Pomerium namespace (for `corp`/`owners` endpoints), and **from other pods in this namespace** — pod-to-pod traffic inside your own namespace works on any port (e.g. your app → your own model/worker/cache pod)
  - Egress: DNS (UDP/TCP 53), HTTP/HTTPS (80/443) **to public addresses only**, intra-namespace (pod IPs and your namespace's ClusterIP Services — the operator keeps `dap-egress-services` in sync automatically), OTLP to the telemetry collector (`http://alloy.infra-alloy.svc.cluster.local:4318` only — the policy pins the collector address, not just the port), PostgreSQL RDS (5432)
  - HTTP/HTTPS egress cannot reach private/internal ranges (RFC1918, CGNAT) or the cloud metadata endpoint (169.254.169.254) — no cross-namespace or kube-apiserver access over 80/443
  - All other egress is blocked
- **Opting a pod out of egress (`ai.paas.dodois.io/egress: restricted`)** — put that label on a pod
  and it loses every path that leaves the cluster: internet 80/443, **object storage (your buckets —
  the cloud endpoints are reached over the same 80/443 rule)**, the LLM proxy and the platform
  databases. It keeps DNS, traffic inside this namespace (pod IPs and your ClusterIP Services) and
  the OTLP collector. Intended for workers that execute untrusted or model-generated code. Pods
  without the label are unaffected.
  - The pattern that makes this usable: keep the worker as pure compute and put everything that must
    reach outside — your own proxy, a local collector, pgbouncer, whatever fetches from a bucket — in
    **another pod of the same namespace**, unlabelled. The worker talks to it over intra-namespace
    traffic. Losing bucket access is deliberate, not an oversight: a bucket with `access: public` is
    a ready-made exfiltration channel — write there, read it off the internet.
  - Self-check, must fail (note the sleep — see caveats): `kubectl exec <pod> -n hackathon-clip-deck -- sh -c 'sleep 20; curl -m5 https://api.github.com'`
  - WARNING - caveats, read them, this is not a sandbox:
    - Policies are programmed a few seconds AFTER a pod starts, so a fresh pod has unrestricted
      egress for 1-3 s (occasionally longer). If that matters, delay your workload with an
      initContainer that sleeps ~30 s — the pod network exists from pod start, so by the time the
      main container runs the rules are in place.
    - DNS stays open to any address, because resolution has to work. DNS tunnelling is therefore
      still possible and we cannot close it here.
    - Other pods in this namespace keep full egress and intra-namespace traffic is allowed — so a
      labelled pod can use an unlabelled neighbour as a relay. Full separation means putting the
      workers in their own project/namespace.
    - The label lives on your pod, so code running inside it can remove it IF it has a token with
      rights to patch pods. Set `automountServiceAccountToken: false` on such workers.
- **ResourceQuota:** enforced — pods exceeding CPU  / Memory  total will fail to schedule
- **LimitRange:** every container must have resource requests/limits (defaults: 100m/128Mi request, 200m/256Mi limit)
- **Namespace isolation:** no access to other namespaces, no ClusterRole/ClusterRoleBinding
- **Forbidden:** privileged containers, hostPath volumes, host PID/IPC, privileged ports (<1024), sysctls, seccomp override
- **Deletion protection for data:** dropping `database`, `mongodb`, `redis` or a `buckets[]` entry from your project manifest destroys that resource with its data. Admission rejects such an edit unless the manifest also carries a confirmation annotation, one token per resource removed (`buckets/<name>` for a bucket):
